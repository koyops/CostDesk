# 成本台 CostDesk · 保健品 OEM 报价工作台

> 一个给保健品代工行业采购/项目人员用的报价工具。
> **单文件离线运行**，双击即用，不装环境、不连网、不依赖服务器。

![主界面](screenshots/main-2x.png)

---

## 一、它解决什么问题

保健品 OEM 代工报价，长期依赖 Excel。真实痛点是三个：

| 痛点 | 具体表现 |
|---|---|
| **口径不统一** | 原料损耗、包材损耗、生产损耗，三个人的算法三样；开模费有的按单分摊、有的不算 |
| **不可审计** | 公式散落在几十个单元格里，报价出去被客户问"这个数怎么来的"，答不上来 |
| **经验绑定个人** | 老业务员一走，报价逻辑就断了；新人接手要重新摸一遍 |

**结果**：一个 SKU 报价 40 分钟，改一次参数全表重算，且容易算错——而报价错一次，可能亏掉整单利润。

## 二、这个工具做了什么

### 1. 全链路成本核算（可审计）

```
原料成本 = Σ(含量% × 单份克重 × 单价/1000) × (1 + 原料损耗%)
包材成本 = Σ[(单价×(1+包材损耗) + 印刷费 + 开模费÷MOQ) × 用量] × (1 + 生产损耗%)
成本合计 = 原料 + 包材 + 加工费 + 检测费 + 运费 + 管理费 + 定制溢价
报价     = 成本 × (1 + 目标利润率)，支持含税/不含税两种口径
```

**三层损耗率独立可调**——这是这个工具和普通 Excel 报价表最大的区别。

### 2. 三档报价与阶梯重算

- **保本价** / **目标价** / **报价价**
- MOQ 变化时自动重算（开模费按订单量分摊，量越大单件越低）
- 低于利润率警戒线自动标红

### 3. 三种录入方式

| 方式 | 说明 |
|---|---|
| **手动录入** | 原料库 / 包材库 / 配方库，一次录入长期复用 |
| **AI 识别（可选）** | 拍照或截图报价单 → 视觉模型提取 → 自动填充 |
| **本地解析** | 粘贴文本报价单/配方，规则引擎解析（不需要联网、不需要 API） |

### 4. 报价存档与复用

历史报价可存档、可回溯、可一键载入复用。「最近使用」自动回填。

### 5. 一个顺手做的桌面宠物

二次元猫娘立绘，7 层表情贴图（睁/闭/笑/思考/惊讶/委屈/睡）× 3 种体型，带养成系统（喂糖、进化、经验）。
贴图为 204×320 RGBA 单帧，转 **WebP(q82) 后 base64 内联**——15 张 PNG 共 620KB，内联后仅 90KB，仍保持"单文件、零外链、断网可用"。
**纯属给自己加乐趣，不影响主功能**——但它撑起了 300+ 项测试。

## 三、工程质量（这部分是重点）

| 指标 | 数据 |
|---|---|
| 成品体积 | 555 KB 单文件 |
| 外部依赖 | **0**（零外链、断网可用） |
| 源码规模 | 14 个源文件 / 12 个 JS 模块 |
| **自动化测试** | **821 项，11 套件，全绿** |
| 构建 | 确定性合并，同源码重复构建**字节级一致**（带 sha1 基线） |
| 版本迭代 | **V7 → V14，8 个大版本** |

### 测试分布

| 套件 | 项数 | 覆盖 |
|---|---|---|
| calc | 27 | 核算引擎：成本构成、含量校验、税费、利润率 |
| parse | 27 | 解析引擎：多格式报价行、单位换算、MOQ/交期剥离 |
| smoke | 186 | 结构契约、关键 DOM、四板块重置、识别入口、存档闭环 |
| V7–V13 | 467 | 各版本特性回归 |
| **V14** | **114** | 门禁：8 项自检 + 老档回填 + 零回归 |

### 三条工程约束（写进构建脚本强制执行）

1. **源码禁止出现 `</script>` 字面量**——否则破坏单文件内联结构，build 直接抛错
2. **测试跑的是构建产物**——改源码不 build，测试跑的还是旧代码（本项目最容易踩的坑）
3. **改 DOM 必须同步改测试断言**——契约同步，不允许"删断言凑绿"

### 三个关键设计决策

**① 为什么是单文件？**
工厂的电脑装不了 Node、装不了环境，甚至没网。**要能在任何一台 Windows 电脑上双击就跑，只有单文件这条路。**

**② 为什么 calc.js 是纯函数？**
核算逻辑必须可测试、可审计。所以 `calc.js` 不碰 DOM、不碰 localStorage，输入对象、输出对象，单元测试直接断言。

**③ 为什么贴图要转 WebP 而不是直接内联 PNG？**
15 张 204×320 的 PNG 合计 620KB，base64 后约 830KB，会把单文件撑到 1.4MB。
转 WebP(q82) 后总共 67.8KB（体积降到 11%，肉眼几乎无差），base64 后仅 90KB。
**约束没变，只是换了一种编码方式**——依然是零外链、断网可用。

## 四、快速开始

**想用**：双击 `CostDesk-V14.html`，浏览器打开即用。

**想改代码**：
```bash
cd src
node build.js          # 输出到上一级 CostDesk-V14.html
```

**想跑测试**（需要 jsdom）：
```bash
cd src
NODE_PATH="<node_modules路径>" node test-v14.js
```

## 六、已知限制（诚实说明）

- **数据需要积累**：这是"越用越好用"型工具。第一周要录 30 个常用原料，之后就不用再录了。**它不是开箱即用的 SaaS，是个人/小团队的成本计算器。**
- **单机单用户**：数据存在浏览器 localStorage，不跨设备同步。
- **手机端不适配**：为桌面场景设计（工厂报价都在电脑上做）。
- **AI 识别是可选增强**：不配置 API 也能用本地解析。

## 七、为什么做这个

在一家保健品代工厂做 OEM 项目专员，每天的工作就是：客户要报价 → 打开 Excel → 翻上一个项目的表 → 改参数 → 算 → 发出。

Excel 能算，但**算得对不对、能不能复用、换个人还算不算得对——这三个问题它都答不了**。

所以做了一个把"报价"从**个人手艺**变成**可审计模型**的工具。
