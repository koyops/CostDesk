## 一、P0 根因：识别三按钮「点击无反应」

### 真根因（事件绑定链路缺失，非样式/选择器问题）

`app.js` 的 `init()` 只初始化了 `calcView / libsView / quotesView`，**从未调用 `global.WB.recognize.init()`**。

`ui-recognize.js` 的三个识别按钮（`btnImgRecognize` / `btnTextRecognize` / `btnFileRecognize`）、识别历史按钮、空状态四入口卡片的 click 事件，**全部在 `recognize.init()` 里绑定**。`init()` 未被调用 → 事件从未挂上 → 点击按钮没有任何反应，也不报错（不是死按钮样式问题，而是根本没有监听器）。

### 修复

`src/app.js` `init()` 在视图初始化后补一行（含防御判断）：

```javascript
if (global.WB.recognize && global.WB.recognize.init) global.WB.recognize.init();
```

### 附带加固（保证「零依赖可用」与「无死按钮」）

1. **OCR 可用性静默探测**：新增 `probeOcrAvailability()`（在 `recognize.init()` 末尾执行）——若 Tesseract 已加载则正常；否则尝试加载 CDN，**失败即调用 `hideImgEntry()`** 隐藏图片识别按钮与空状态卡片。图片入口**只会在 OCR 真正可用时出现**，绝不显示「点了没反应」的死按钮。
2. **点击直降级**：`_tesseractFailed` 标志置位后，用户再点图片入口（如已隐藏、残留缓存 DOM）直接弹出「手动粘贴图片文字」面板 + toast 提示，不走选图→失败的无用链路。
3. **文字识别 / 文本配方零依赖**：两条链路纯本地（正则解析 + FileReader 提取 TXT / 内置 ZIP 解包 docx/xlsx），与 OCR CDN 完全解耦，OCR 不可用**绝不影响**这两个入口。

### 排查中发现并一并修复的既有缺陷

- **确认面板「补一行」插多行**（影响「确认面板全操作」验收）：`bindRowEvents()` 每次 `render()` 都执行，而 `#recAddRow` / `#recMatchAll` 位于 `#recRows` tbody **之外**（`.rec-ops` 常驻区），不会被 `innerHTML` 重建 → 每次 render 往同一按钮叠加一个监听器 → 点一次「补一行」实际插入多行、点击「一键匹配」重复执行。修复：两按钮改为**弹窗创建时一次性绑定**，`bindRowEvents` 只负责 tbody 内随行重建的元素。
- **v2 备份导入后原料清单渲染崩溃**：`matLineHtml()` 对 `mat.suppliers` 无判空，导入 v2 备份（原料无 `suppliers` 字段）后添加原料会抛 `Cannot read properties of undefined`。修复：`if (mat && mat.suppliers)` 判空。

## 二、P1 新增：配方一键清除

- **入口**：原料清单卡片标题栏右侧 `.card-actions` **最前**，与「一键最优价」「添加原料」同行，文案「清除配方」（垃圾桶图标 + 红色 `btn-danger`），tooltip 说明范围。
- **二次确认**：点击弹出「清除配方」确认框，文案含 **「确定清空当前配方？此操作不可恢复」**，并明确列出将移除的行数与「仅清空报价草稿，不影响价格库/模板/报价记录」；底部勾选框「同时清空包材清单与产品参数（方案名/客户/克重/每瓶数量等）」（**默认不勾选，只清原料清单**）。
- **确认后行为**：
  - 原料清单 `mats=[]` → 渲染空状态引导（「还没有原料。点击右上角 ＋ 添加原料…」）；
  - 勾选连带时：包材 `packs=[]` + 产品参数重置（方案名/客户/净含量/箱规/克重/每瓶数量/配方/剂型/动态字段）；
  - 结果区 `resetResult()`：成本明细回归初始空状态、总成本归零、状态「待核算」、清空上次核算缓存；
  - 顶部操作栏摘要同步刷新；toast「配方已清空」。
- **边界**：配方已为空时点击 → toast「当前配方已是空的」不弹框；取消 → 无任何变化；**不删除**原料价格库、包材价格库、配方模板、历史报价记录。
- **保留**：商务参数（MOQ/税率/利润率等）不随连带清空重置（属策略性报价设置，非产品参数）。

## 三、三按钮完整链路演示（测试 V5-D，真实按钮点击）

| 入口 | 用户操作 | 链路断言 |
|---|---|---|

| 文本配方 | 点击 `btnFileRecognize` → 选 TXT → 内置提取 → 同解析内核 | TXT 提取出「维生素C」✓；按钮事件绑定生效不报错 ✓ |
| 图片识别 | 点击 `btnImgRecognize` → 选图 → OCR 识别中（进度条）→ 结构化 | OCR→识别确认面板 4 行（含辅料）✓ |
| OCR 不可用 | `hideImgEntry()` → 图片按钮与空状态卡片隐藏 | 点击隐藏按钮直降级出 `#ocrText` 粘贴框 ✓；文字识别仍可用 ✓ |

## 四、清除配方全流程演示（测试 V5-E）

1. 记录清除前原料/包材/价格库/报价数 → 点击「清除配方」→ 二次确认框出现 ✓
2. 点「取消」→ 原料清单无变化 ✓
3. 再点「清除配方」→ 直接确认（默认只清原料）→ 原料 0 行 ✓、包材保留 ✓、空状态引导 ✓、结果区「待核算」+ 初始空状态 ✓、价格库/报价数不变 ✓、toast「配方已清空」✓
4. 连带场景：临时塞入原料+包材 → 勾选「同时清空包材清单与产品参数」→ 确认 → 原料 0、包材 0、方案名重置为空 ✓
