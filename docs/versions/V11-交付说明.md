## 一、A. 桌宠消失根因修复（#72）

**现象**：部分老用户升级后页面右下角桌宠不再渲染（其它功能正常）。

**根因**：桌宠持久化沿用键 `WB_PET_V2`，而 V6–V9 版本在该键下保存的是**多精灵存档**——`active` 可能为 `fire/elec/sky`（精灵物种）、`pets` 可能是旧数组/旧结构、位置记忆存于顶层 `x/y`。V10 起渲染逻辑只认识单橘猫（`cat`），遇到这类旧档在读取/渲染时直接中断，导致宠物整体缺失；`localStorage` 损坏（非法 JSON）同样会让加载路径抛错中断。

**修复（三层防御，均已进 `ui-pet.js`）**：
1. **加载归一化 `load()`**：`pets` 非对象或为数组 → 重置为默认对象结构；`active` 不在已知物种表 → 回退 `cat`；`unlocked` 非法 → 回退默认；旧顶层 `x/y` → 自动迁移为 `pos` 保留位置记忆；JSON 损坏 → 静默使用默认值，不抛异常。
2. **渲染防御 `render()`**：物种异常二次回退橘猫并落盘；每次渲染自愈。
3. **启动幂等 `init()`**：`#petRoot` 不存在时安全返回；重复 init 不叠加定时器、不丢失渲染。

**自测**：`test-v11.js` 场景 B/C 覆盖 4 类危险存档——旧多精灵存档（active=fire + 顶层 x/y）、损坏 JSON、无猫存档（active=sky）、旧数组 pets 结构——全部 0 console.error 且渲染出默认橘猫；旧物种的昵称/连胜/喂食次数**不误嫁**到橘猫；**切板块（核算台↔原料价格库）与二次 init（模拟刷新）后桌宠仍在**。

## 四、D. 四板块独立重置 + 一键全重置（#75）

| 入口 | 按钮 | 清空范围（当前录入态） |
|---|---|---|
| 产品参数卡头 | **重置**（`btnResetProd`） | 方案名称/客户/日期/配方方案+版本/剂型/动态参数/克重/每瓶数量/净含量/装箱/项目/类型/注册/备注 |
| 商务参数卡头 | **重置**（`btnResetBiz`） | MOQ/工厂起订量/阶梯/计价口径/税率/利润率/管理费/人工/定制溢价/检测费/运费/汇率/损耗率 → 恢复默认（MOQ 5000、税率 13、利润率 30、人工…） |
| 原料清单卡头 | **重置**（`btnResetMats`） | 清空全部原料行（配比/供应商/价格选择） |
| 包材清单卡头 | **重置**（`btnResetPacks`） | 清空全部包材行（每瓶用量设置） |
| 核算台顶部工具区 | **全重置**（`btnResetAll`） | 以上四个板块全部清空 → 核算面板回到**待核算**态 |

**交互契约**：
- 每个入口都弹**确认框**（标题随板块变化），可**取消**——取消不执行任何变更、弹窗关闭；
- 确认后只清对应板块录入并实时联动刷新表单/清单/顶部汇总；`stopPropagation` 防止误触卡片折叠（重置按钮点击不会折叠/展开卡片）；
- 原料、包材清空后核算面板回到待核算空状态；仅清单板块而其它板块仍有内容时结果栏按剩余输入**实时重算**；
- 全重置文案明确提示范围与影响面：「将清空四个板块的全部录入，核算面板回到待核算态，是否继续？」+ 灰色小字「仅清空当前录入态，不影响原料价格库/包材库/配方库/报价存档/设置/宠物数据」。

**自测**：五个按钮逐一弹出确认框 → 取消无副作用（state 快照一致）→ 确认后逐板块断言：产品参数只清产品、商务参数恢复默认但原料/包材保留、原料清单只清行（价格库条目数不变）、包材清单只清行；全重置后四板块全空、表单同步、结果栏回「待核算」。
